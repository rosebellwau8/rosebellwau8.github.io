AI agent（workbuddy、codex、Qwen Code 这一类能干活的 AI）本事再大也是「通才」：它不知道你家周报长什么样，不知道你博客的排版规矩。想让它变成「懂你的专才」，不用写代码，答案是一个文件——skill（技能）。这篇全程真机实操：从零手搓一个「周报生成器」技能，放进 workbuddy 和 codex，当场调用验证。文中每条命令都是刚跑过的。

一、skill 到底是什么

拆开看，一个 skill 就是「一个文件夹＋一个说明书」：

weekly-report/          ← 技能文件夹，名字即技能名
├── SKILL.md            ← 必须有，唯一的硬要求
├── references/         ← 可选，参考资料
└── assets/             ← 可选，模板、图片等素材

核心全在 SKILL.md，开头是一段叫 frontmatter 的登记信息（用两行 --- 包住），后面是正文：

---
name: weekly-report
description: 把零散的工作记录整理成结构规范的周报。当用户说「写周报」「生成周报」时使用。
---

# 周报生成器
（正文：这个技能干什么、按什么步骤干、有什么规矩）

两个字段分工明确：

  • name：技能名，和文件夹同名。
  • description：最要紧的一个字段。agent 不会通读你的正文，它靠这句话判断「用户现在的需求要不要叫这个技能」。写不清，技能就永远在睡觉。
实测发现，技能目录不止一个。本机 codex 启动时同时扫描了 .codex\skills（约 70 个技能）和 .agents\skills（多工具共享目录）；workbuddy 用 .workbuddy\skills，Qwen Code 用 .qwen\skills——三家格式完全同源，搓一个，处处能放。
工具技能目录（本机实测）
workbuddyC:\Users\yuankang\.workbuddy\skills
codex CLIC:\Users\yuankang\.codex\skills（另扫描 .agents\skills）
Qwen CodeC:\Users\yuankang\.qwen\skills

二、搓之前：确认环境

先确认 codex 在场：codex --version，本机输出 codex-cli 0.146.0。再用 dir /b 看两个技能目录，都有内容即就位。codex 目录里自带一个 template-skill，打开就是官方最小骨架——frontmatter 两行加一句「在下面写指令」，照着填即可。

三、手搓：weekly-report 诞生

本次目标：让 AI 把零散的工作记录变成能直接上交的周报。新建文件夹 weekly-report，写 SKILL.md（真实生效版本，此处略有删节）：

---
name: weekly-report
description: 把零散的工作记录整理成结构规范的周报。当用户说「写周报」「生成周报」「整理一下本周工作」「weekly report」「本周总结」时使用。先收集本周做的事，再按固定四段格式输出，突出进展与风险，不编造未完成的工作。
agent_created: false
---

# 周报生成器

## 步骤
1. 收集素材：请用户提供本周做的事；素材不足就问，不许编。
2. 归类：把事项归入「已完成 / 进行中 / 下周计划 / 风险与求助」四类。
3. 按固定四段格式输出，每条一行，动词开头，写结果不写过程。

## 要求
- 每条不超过 40 字，能带数字就带数字（「修了 3 个 bug」优于「修复若干问题」）
- 不夸大、不虚构；素材里没有的不写

写的时候拿住三个要点：

description 要写「干什么＋什么话触发」

对比机上一个真实技能：「把文章转换为符合博客规范的 HTML 文件……当用户要求转成 HTML、排版成 HTML、做成网页时触发」——功能和触发词都摆明了，agent 一听见关键词就会调用。只写「处理周报」四个字，agent 大概率想不起来你。

正文写步骤和禁令，不写散文

agent 是把说明书当操作手册执行的，「素材不足就问，不许编」这种硬规矩，写一条生效一条。

格式输出要给定死的结构

我规定了四段式模板，后面实测时它就一字不差地照办了。

顺带一提：agent_created: false 是 workbuddy 端的附加字段，标记「这是人手搓的，不是 AI 生成的」，没有也不影响。

四、放进两个工具

skill 不需要「安装」，把文件夹放进技能目录就生效。本机操作（两个工具各来一遍）：

mkdir C:\Users\yuankang\.codex\skills\weekly-report
copy SKILL.md C:\Users\yuankang\.codex\skills\weekly-report\
dir /b C:\Users\yuankang\.codex\skills\weekly-report

workbuddy 同理，目录换成 C:\Users\yuankang\.workbuddy\skills。没有注册、没有重启服务——文件到位，技能就位，下次会话即被加载。

五、当场实测：codex 真的调用了它

一条命令验证，让 codex 用新技能写周报（素材随手给）：

codex exec --sandbox read-only "使用 weekly-report 技能，帮我写一份本周周报（素材：本周完成了 skill 教程文章写作、weekly-report 技能搭建；进行中：红楼梦续写第二折 60%；下周计划：完成第86-90回）"

日志显示它先主动读取了技能文件：Get-Content ... .codex\skills\weekly-report\SKILL.md，随后产出：

# 周报（2026-08-03 当周）

## 本周完成
- 完成 Skill 教程文章写作
- 搭建 weekly-report 技能

## 进行中
- 推进《红楼梦》续写第二折，完成度 60%

## 下周计划
- 完成《红楼梦》续写第 86—90 回

## 风险与求助
- 无
四段格式、动词开头、无中生有的内容一个没有——正文里的规矩全部生效。本次调用消耗 11,438 tokens。

六、踩坑与心得

实测路上捡到两个真坑，都值得一说。

坑一：frontmatter 坏了，技能静默失踪

codex 启动日志里有一行报错：failed to load skill ...\.agents\skills\video-frames-1.0.0\SKILL.md: missing YAML frontmatter delimited by ---。这个技能文件还在目录里，但因为开头少了两行 --- 包住的登记信息，加载直接失败。技能「装了但没人认」是最典型的静默故障——技能不灵时，先查 frontmatter 格式。

坑二：Windows 下的编码

同一次实测里，codex 用 PowerShell 读取技能文件时，日志里中文成了乱码。稳妥起见：技能文件一律 UTF-8 保存，PowerShell 读取时加 -Encoding UTF8。

最后把心得压成五句话：

  1. 一个文件夹＋一个 SKILL.md 就是一个技能，放进技能目录即生效，无需安装。
  2. description 决定技能会不会被想起来：写清「干什么＋什么话触发」。
  3. 正文写步骤、写格式、写禁令，agent 照章办事。
  4. 技能不灵先查 frontmatter 两行 --- 是否完整。
  5. 同一份 SKILL.md，workbuddy、codex、Qwen Code 通用——搓一次，三处可用。
把你每天重复交代 AI 的那套话写进一个 SKILL.md，这就是手搓 skill 的全部秘密。
