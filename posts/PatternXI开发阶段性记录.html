当前阶段与总体完成度

Pattern XI 已经从「方案设计期」跨进了「可信发布内核已跑通，剩余主要是生产化与展示化」的阶段。当前总体完成度估在约 55%–65%。如果只看最难、最容易返工的「规则与可信链路」，完成度更高，大约 70%–80%；如果看「真正上线并开始 90 天倒计时」，还差持久化、公开读取、部署和运营闭环，所以不能估得太乐观。

已经真正完成的部分

最核心的一条链已经闭合：

私人生产结果→ Transfer Boundary→ 签名 publication package→ Evidence→ 独立验证→ final cutoff→ public_pick_id→ official_at→ OFFICIAL

这很重要，因为这不是页面原型，而是定义了可信内核。而且每个阶段都有独立 checkpoint、CI、tag 和回退点。

现在已经有：

  • Stage 1 合同基线；
  • PRICE001；
  • Transfer Boundary offline slice；
  • Evidence vertical slice；
  • Publication Core vertical slice；
  • GitHub Actions CI；
  • 多个不可移动 checkpoint tag；
  • 生产侧一键流程和 Crown FT AH enrichment；
  • 生产侧结构化 public export。

这意味着最容易出现概念错位的部分（价格语义、Pattern历史、结算边界、Evidence语义、OFFICIAL时机）都已经被真实数据撞过一轮，且修正后冻结。

尚未完成的主要部分

剩下的工作大致可以分成四块。

第一块：生产级持久化

目前 Publication Core 仍然依赖 test-only file store。真正上线前，需要把状态、Official records、幂等、序列、outbox 等搬到正式 PostgreSQL / 生产级存储。

第二块：公网接收与公开读取

现在核心链路能「证明一条 review 成为 OFFICIAL」，但还没有真正的 public receiver、read model、Today / Track Record / Pick Detail 等页面。

第三块：部署与恢复

Vercel / 服务器、数据库、独立 public-records repo、备份恢复、监控、Assume-Breach 这些还没有真正落地。

第四块：Settlement + 90-Day runtime

结算规则已经定义，但还没接入正式运行链；90-Day clock、Shadow Run、Daily Manifest、正式 Day 1 也都还没开始。

所以当前状态可以概括为：「可信推荐发布内核完成，产品外壳与生产运行层尚未完成。」

按最初目标看：进度与收工

如果按最初「8–10 个开发日进入 Shadow Run」的目标看，今天这轮推进其实比预期更扎实，但也说明原先的 8–10 天是偏乐观的时间盒，而不是可靠工期。前几天大量时间花在了真实合同冲突的发现与纠正，这是值得的，因为这些问题一旦进入数据库和公网 Evidence，再改会贵很多。

现在反而进入了相对更机械的阶段：

把已正确的内核搬进正式 persistence → 接 public read model → 接最小 UI → 接 settlement → 部署 → Shadow Run

如果继续严格不扩范围，距离「可以开始 Shadow Run」大概还需要 5–8 个高质量开发日；距离真正 Day 1，大概还要再加至少 7 天 Shadow Run。

最烧脑的那一半基本过去了，后面更多是工程落地。

当前 main、CI、tag、工作树都干净，没有半截任务悬着，明天可以从一个很清晰的 checkpoint 继续。
