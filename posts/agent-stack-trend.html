曾经在 OpenAI 的模型指南里读到一组数字：他们内部 coding agent 评测时把 system prompt 精简了，结果分数反而提高了十几个百分点，token 消耗少了一半，成本降低了三分之一到三分之二。官方建议，可以试着逐组删掉重复指令、示例和无关的工具说明，然后重新跑代表性任务看看。

删东西，性能变好？

一年前，满世界都还在教怎么写咒语：角色设定、思维链、少样本、输出格式约束，一个提示词模板动不动两千字，社群里还有人卖 Prompt 大全。现在官方评测却表明，精简 prompt，效果反而更好。

那日常工作里，prompt 技巧还要不要学？进一步地，skills 还要不要装、要不要做？以及别人换了新 harness，要不要跟着换？

这三个问题困扰了我很久。

刚刚抽空用 agent 收集了 14 个一手来源研究，有 Anthropic 和 OpenAI 的工程博客，有 METR 的评测方法说明，还有两篇专门做脚手架消融的预印本，并总结了一下，结果发现：网上那些"Prompt 工程已死"和"Agent 时代人人都要会搭脚手架"，各自只说出了一半真相：

如果只看固定任务、固定质量标准，顶级模型需要的 prompt 确实更少。但如果看的是能长期跑、跨工具跑，并留下审计痕迹的 Agent 系统，那 skills 和脚手架总量是在上升的。

减少的是每次你亲手喂给模型的显式指挥。知识、约束和验证本身没少，只不过部分被模型内化了，部分从聊天框搬到了仓库、skill 和代码里。

也就是说，前台在变薄，后台在变厚。

那么Prompt 到底还要不要学？

答案是要学，但内容变了。

以前学 prompt，学的是怎么把每一步措辞写对，怎么堆少样本、怎么设角色。现在顶级模型内化了部分规划、长上下文和自检能力，你再手把手从外部教它，反而可能带来内外规则矛盾，搞得模型不得不去调和，额外浪费算力，甚至引起降智。

Anthropic 有一组跨了好几代模型的连续案例。Sonnet 4.5 的时候，长任务跑着跑着上下文就糊了，得做 context reset重置。到 Opus 4.5，这个需求基本消失。再到 Opus 4.6，连 sprint 分解都能删掉，那个负责打分的 evaluator，在模型能力范围内的任务上，已经变成纯粹的额外开销。

那些为旧模型补窟窿的巧妙控制流，下一代模型上来就成累赘了。

如今的 prompt 能力只剩三件事：写清楚目标，给够上下文，明确硬约束和完成标准。剩下的重复规则、没实测收益的人设、过度分步、无关工具说明，都该删。少背模板，多学着写你想要什么、边界在哪、怎样算做完。模型越强，越不需要你教它怎么想，越需要你给对目标和边界。

skills 装不装、做不做？

要，但只留确实值得的。

skill 解决的是模型参数里不可能知道、或者需要确定性脚本的东西。公司的报销流程、团队的品牌规范、某冷门工具的正确调用姿势，这些再聪明的模型也不可能凭空变出来。

2025 年，Anthropic 把 Agent Skills 做成了跨平台标准，核心机制叫渐进披露，启动时只载入几十个 token 的名字和描述，任务命中了才逐层加载全文。skills 库存因此几乎可以无限扩张，平时只占一点上下文，用到才展开。

OpenAI 用 Codex 做 agent 化改造，耗时大约五个月，1500 个 PR，上百万行代码，根目录 AGENTS.md 却只有大约 100 行，仅作地图用。真正撑住系统的，是背后的结构化知识库、可观测性、隔离工作树、linters、结构测试，还有一个专门维护文档的 agent。

入口短得像便签，背后却是一整套基础设施。

装 skills、做 skills 都值得，但别为了囤而囤。删掉一个 skill 后，哪个任务会变差？答不上来就别留。一段流程是不是近期反复在用，用就做成 skill，而不是去装一堆用不上的花活。

harness 追不追新？

别追新，追刚好覆盖你风险的那个。

有一篇叫 The Scaffold Effect的研究，发现固定两个模型，在三个开源 harness、50 个任务上跑 300 次，不同 harness 之间，每解一题消耗的 token 最多能差 40 倍，但配对通过率只差 0 到 8 个百分点，而且会出现可以复现的、某个 harness 特有的失败模式。

另一篇叫 Harness-Bench的研究则发现，106 个离线任务、5194 条轨迹，可配置 harness 的聚合分数能差出 23.8 分，同时它还证明，模型越强，跨 harness 的方差越低，也就是更能容忍不同的 prompt、工具接口和状态设计。

这两个研究说明，脚手架决定的，是成本、等待时间、失败方式和监督成本，但它不能让模型更聪明。它不一定让 agent 更会做事，却强烈决定会花多少钱、等多久以及用什么姿势翻车。

那是不是多 agent 就更好？不一定。Anthropic 的内部评测里，多 agent 系统比单 agent 的 Opus 4 高了 90.2 个百分点，代价是大约 15 倍于普通聊天的 token。它适合可并行的广度研究，不适合依赖强、共享上下文多的任务。2024 年 Anthropic 就提醒过，简单可组合的模式往往优于复杂的框架，这条经验今天还成立。

结论

总起来说吧，模型越聪明，逐步 prompt 越该删，skills 和脚手架越该往后台沉。脚手架还得用，只是干的活变了：从前是教模型怎么想，现在是要给模型提供特殊知识，替它的自主行为兜底。

上面这些证据大多来自编码和浏览研究，还有所局限，谈判、组织管理或者高语境专业工作不能直接套用。如果哪天最强模型用极简 loop 就能在固定长时任务上，把完整系统的成功率、成本、安全和可审计性全都比下去，那"后台变厚"这件事可能就要进入新阶段了。
